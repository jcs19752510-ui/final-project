# aimock AI 모델 검증 보고서 (Model Card)

- 버전: 2026-09-09
- 목적: 이 서비스가 사용하는 4개 AI/신호처리 구성요소 각각에 대해
  용도, 알려진 한계, 검증 범위를 투명하게 기록한다. 별도의 공식
  편향성/정확도 벤치마크 조직 검증은 거치지 않았음을 먼저 밝힌다 —
  아래 각 항목의 "검증 범위"가 실제로 이 프로젝트에서 확인한 전부다.

## 1. 음성 인식(STT) — Groq 호스팅 Whisper API

| 항목 | 내용 |
|---|---|
| 모델 | `whisper-large-v3-turbo`(Groq 호스팅, `app/ai/stt.py`) |
| 용도 | 지원자의 음성 답변을 텍스트로 변환 |
| 채택 근거 | `docs/adr/adr-008-stt-groq-hosted-whisper.md` — 로컬 실행(faster-whisper) 대비 저사양 서버 환경에서 압도적으로 빠름(실측 4.7~수십 배) |
| 검증 범위 | 실제 합성 음성 샘플로 STT 왕복 동작 확인(예외 없이 텍스트 반환). **정확도(WER 등)를 정량적으로 측정한 적은 없음** |
| 알려진 한계 | (1) Whisper 계열 모델은 배경 소음/억양/방언에 따라 정확도가 크게 달라질 수 있음(공개적으로 알려진 한계, 이 프로젝트에서 별도 검증 안 함). (2) 한국어 억양·사투리별 정확도 편차를 이 프로젝트에서 측정하지 않음 — **인구통계 그룹별 성능 차이(공정성) 검증 없음**. (3) 음성 원본이 Groq 서버로 전송됨(개인정보 처리방침 §4 참조) |

## 2. 대화 생성/채점(LLM) — Groq 호스팅 대형 언어모델

| 항목 | 내용 |
|---|---|
| 모델 | `openai/gpt-oss-120b`(Groq 호스팅, `app/ai/llm.py`/`app/ai/report.py`) |
| 용도 | 면접 질문 생성(맥락 기반 꼬리질문), 답변 평가/채점, 리포트 요약 |
| 채택 근거 | 무료 티어 한도가 Gemini 대비 넉넉함(2026-09-08 실측 확인, `app/ai/providers.py` 주석) |
| 안전장치 | 시스템 프롬프트에 "인종·성별·억양 등 인구통계적 특징은 절대 언급하거나 평가에 반영하지 마십시오" 명시(`app/ai/llm.py`, `app/ai/report.py`). 응답이 지정된 JSON 스키마를 벗어나면 안전한 폴백 값으로 대체(`_parse_or_fallback`) — 서비스가 죽지 않음 |
| 검증 범위 | (1) 스키마 불일치 시 폴백 동작을 자동화 테스트로 검증(`test_u3a_ac4_llm_schema_violation_falls_back`). (2) 빈 답변에 대해 실제로 낮은 점수가 나오는지 실사용 중 확인(임의로 높은 점수를 주지 않음). **(3) 인구통계적 특징에 따라 실제로 평가가 달라지는지(편향)는 자동화 테스트가 없었음** — 2026-09-09 이후 추가 예정(별도 작업 항목) |
| 알려진 한계 | (1) LLM 특성상 같은 입력에도 매 호출 결과가 조금씩 달라질 수 있음(비결정적). (2) "하지 마라"는 프롬프트 지시가 실제로 항상 지켜지는지 대규모로 검증하지 않음 — 프롬프트 수준의 안전장치이지 구조적으로 편향을 차단하는 필터가 아님. (3) 질문 후보 검색(RAG)이 실제로는 벡터 유사도 검색이 아니라 카테고리/난이도 필터+무작위 추출(`docs/trd/aimock_u3a_trd.md` §7) — 원안 대비 축소된 방식 |

## 3. 표정 분석 — DeepFace

| 항목 | 내용 |
|---|---|
| 모델 | DeepFace 기본 감정 분류 모델(`opencv` 얼굴 검출 백엔드, `app/ai/emotion.py`) |
| 용도 | 답변 중 캡처된 얼굴 프레임에서 지배적 감정(neutral/happy/sad 등) 추정 |
| 검증 범위 | 얼굴이 검출되지 않는 이미지에 대해 예외 없이 안전한 폴백값("unknown")을 반환하는지만 자동화 테스트로 확인(`test_ac3_no_face_detected_returns_unknown_not_exception`). **실제 얼굴 이미지로 정확도를 측정한 적은 없음** |
| 알려진 한계 | (1) 얼굴 표정 인식 모델 일반의 잘 알려진 한계로, 조명/각도/카메라 화질에 따라 정확도가 크게 떨어짐 — 실사용 중에도 표정 인식이 계속 "unknown"으로만 나오는 문제를 발견한 바 있음(`내부테스트결과서/리포트화면TRD정합성점검및문서동기화_20260908124216.md`). (2) **얼굴 표정 인식 모델은 학계에서 인종·성별에 따른 성능 편차가 보고된 사례가 다수 있는 분야**인데, 이 프로젝트는 그런 편차를 별도로 검증하지 않았음 — 평가 결과가 아니라 "참고용 비언어적 신호"로만 리포트에 노출되는 것이 그나마의 완화책 |

## 4. 음성 운율 분석 — librosa (피치/에너지)

| 항목 | 내용 |
|---|---|
| 방식 | 머신러닝 모델이 아니라 결정론적 신호처리 알고리즘(`librosa.pyin` 피치 추정 + RMS 에너지 계산, `app/ai/prosody.py`) |
| 용도 | 답변 음성의 평균 피치(Hz)·발화 에너지 산출 |
| 검증 범위 | 실제 합성 음성으로 피치 탐지 정확도(주입한 주파수 대비 오차 2% 이내) 및 처리 속도(3.16초→0.69초로 최적화, 정확도 손실 거의 없음) 실측 확인 완료(`내부테스트결과서/U3b보완_음성운율분석속도개선및로깅수정_20260908195613.md`) |
| 알려진 한계 | (1) 결정론적 알고리즘이라 "편향"의 개념 자체가 ML 모델과 다르지만, 배경 소음이 많거나 무음에 가까운 오디오에서는 신뢰도가 떨어짐(폴백값 0.0으로 처리). (2) 2026-09-09 기준 운영 환경(Render)에서 이 분석이 20초 제한 시간 내에 끝나지 않아 폴백값만 나오는 문제가 관찰됨(원인 미확정, `내부테스트결과서/보안강화F4_AES256GCM전환_20260909120115.md` §5) |

## 5. 종합 — 이 보고서가 커버하지 않는 것

- 각 모델에 대한 정량적 편향(bias) 벤치마크(예: 특정 그룹 답변에 대한
  점수 분포 비교)는 이 문서 작성 시점까지 수행되지 않았습니다.
- 프롬프트 수준의 "공정성 지시문"은 있으나, 이것이 실제로 편향을
  막는지 검증하는 자동화 테스트는 별도 작업(전수검사 부록 항목 G
  "편향성 테스트")으로 진행 예정입니다.
- 이 서비스의 평가 결과는 **참고용 보조 도구**로 설계되었으며, 실제
  채용 의사결정을 AI 리포트 하나만으로 내리는 것은 권장하지 않습니다.
