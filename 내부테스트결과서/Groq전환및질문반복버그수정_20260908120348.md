## §2. 사용자 질문에 대한 정확한 답변 — 실측 결과

### Q1. "AI 면접관 인식 못함"(호출 실패)이 Groq로 해결되는가?
**예, 해결됩니다.** 실제 근거:
- 원인이었던 Gemini 429(하루 쿼터 소진)는 애초에 Groq에는 해당 안 됨(별도 서비스, 별도 쿼터)
- 실제 Groq로 회원가입→면접 시작→턴 제출→종료→리포트 생성까지 **전체 흐름을 실제 API로 재현, 전부 200/201 정상 응답**(§3 로그 참조)
- Groq 레이트리밋(분당 1000요청)은 면접 1회(턴 5~15개)로는 절대 소진될 수 없는 수준

### Q2. "동일한 질문을 자꾸 줌"이 Groq로 해결되는가?
**아니요 — 이건 LLM 제공자 문제가 아니라 저희 자체 코드 버그였고, 실제로 그렇게 확인했습니다.**

**재현 실험(수정 전)**: 지원자가 4번 서로 다른(구체적이고 실질적인) 답변을
했는데도, `GroqProvider`가 **"REST API 설계 원칙" 질문을 4번 연속 거의
그대로 반복**하는 것을 실제로 확인함(§4 로그). 즉 **Groq로 바꾼 뒤에도
동일하게 재현** — 모델 문제가 아님을 실측으로 증명.

**진짜 원인**: `question_service.retrieve_candidates()`가 매 턴 질문은행
전체에서 무작위로 3개를 뽑는데, **이미 나온 질문을 다시 뽑는 걸 막는
로직이 아예 없었음.** LLM이 "[참고 가능한 질문 후보]"에 있는 문구를
그대로 베끼는 경향이 있어서, 같은 후보가 재등장하면 같은 질문이 반복됨.

**수정한 것**:
1. `retrieve_candidates()`에 `exclude_contents` 파라미터 추가 — SQL
   `NOT IN`으로 이미 나온 질문 자체를 후보 풀에서 제외.
2. `interview_service.submit_turn()`이 지금까지의 AI 발화 전체를
   `exclude_contents`로 넘기도록 연결.
3. `SYSTEM_PROMPT`에 "후보는 참고용일 뿐 그대로 베끼지 말고, 지원자의
   방금 답변 내용을 이어받아 새 질문을 만들 것 / 이미 나온 질문 반복
   금지"를 명시적으로 추가.

**수정 후 재검증(같은 4개 답변으로 재실행)**: 1~3번째 턴은 **전부
서로 다른, 지원자의 구체적 답변 내용을 반영한 새로운 질문**으로 개선
확인(§4 로그). **단, 완전히 없어진 건 아닙니다** — 4번째 턴은 지원자가
직전(3번째) 질문에 답을 안 하고 다른 주제로 답변하자, AI가 3번째와
비슷한 문구로 같은 주제를 다시 캐물었습니다. 이건 "같은 질문을
기계적으로 반복"이라기보다 "미답변 주제로 되돌아가는" 자연스러운
면접 행동에 가깝지만, 완전히 별개의 새 질문은 아니었습니다.

**결론**: 원래 있던 심한 반복(4연속 동일 질문)은 확실히 해결됨.
"지원자가 질문을 회피했을 때 AI가 그 주제로 다시 돌아가는" 경향은
남아있음 — 이건 버그라기보다 판단이 필요한 영역이라 이번엔 추가로
손대지 않음(원한다면 "지원자가 답을 회피해도 새 주제로 넘어가라"는
프롬프트 규칙을 추가할 수 있음 — 사용자 결정 필요).

## §3. 전체 흐름 실제 API 검증 로그

```
회원가입 → 로그인 → 면접 시작(201) → 턴 제출(200, 실제 질문 생성 확인)
→ 면접 종료(204) → 리포트 생성(201, Groq로 실제 평가 생성 확인)
```
무음 오디오에 대해 리포트가 "답변을 제공하지 않았다"고 정직하게 낮은
점수(1/1/1)를 매기는 것도 Gemini 때와 동일하게 확인(환각 없음).

## §4. "동일 질문 반복" 재현/수정 전후 비교 (실제 Groq 응답 원문)

**수정 전** (같은 2개 후보를 인위적으로 고정 — 실제 앱의 최악 시나리오 재현):
```
턴0: REST API 설계 원칙에 대해 설명해 주시겠어요? ...
턴1: REST API 설계 원칙에 대해 구체적으로 설명해 주실 수 있나요? ...
턴2: REST API 설계 원칙에 대해 구체적인 예시를 들어 설명해 주실 수 있나요? ...
턴3: REST API 설계 원칙에 대해 구체적인 예시를 들어 설명해 주세요. ...
```
→ 4턴 전부 사실상 동일 질문.

**수정 후** (실제 서비스와 동일하게 매 턴 새로 후보 조회 + 이미 나온 것 제외):
```
턴0(후보: 브라우저 렌더링/시간복잡도/REST API): "FastAPI 성능 병목을 어떻게 진단·해결했는지" (자기소개 내용 반영)
턴1(후보: DB인덱스/가장자신있는언어/REST API): "결제 시스템 리팩토링에서 성능 병목을 어떻게 찾고 최적화했는지" (직전 답변 반영)
턴2(후보: React상태관리/어려운기술문제/DB인덱스): "Saga 패턴을 Orchestration/Choreography 중 어떻게 구현했는지" (직전 답변 반영)
턴3(후보: MSA경험/React/팀갈등해결): "(턴2와 유사) Saga 패턴 Orchestration/Choreography, 모니터링 방법" — 지원자가 턴2 질문에 답 안 하고 딴 얘기해서 재질문
```
→ 0~2턴 완전히 다른 질문, 3턴은 "미답변 주제 재질문"(경계선 케이스, §2 참조).
