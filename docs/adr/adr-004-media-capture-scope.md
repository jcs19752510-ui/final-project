# ADR-004: 실시간 미디어 처리 범위 축소 (WebRTC SFU 제거)

- 날짜: 2026-09-07
- 상태: 승인됨
- 결정권자: 사용자(ADR-001 승인에 종속) / AI 초안

## 배경 (Context)

원본 기획서 §4.2.2는 브라우저 P2P가 아닌 **서버 사이드 SFU**(Python aiortc
또는 GStreamer)를 통해 클라이언트의 WebRTC 오디오/비디오 스트림을 서버가
수신하고, 이를 STT/DeepFace로 각각 분기(forking)하는 구조를 전제합니다.
이는 "AI가 실시간으로 영상/음성을 분석해야 한다"는 요구(REQ-F-002)를
충족하기 위한 설계이지만, ADR-001에서 상호작용을 턴 기반으로 확정했으므로
**실시간 분기 처리 자체가 더 이상 필요하지 않습니다.**

## 검토한 대안 (Options)

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 클라이언트 `MediaRecorder` API로 턴 단위 녹화 → 종료 시 오디오/비디오 blob을 REST로 업로드 | WebRTC 시그널링·SFU·미디어 서버 전부 불필요, 표준 브라우저 API만 사용, 구현 최소화 | 진짜 "실시간 화상 통화" UX는 없음(이미 ADR-001에서 감수하기로 확정) |
| B. WebRTC는 유지하되 서버가 아닌 화면에만 로컬 렌더링(녹화는 A와 동일) | 화상 카메라 프리뷰 UX는 동일 | WebRTC를 쓰면서 서버 분기를 안 하면 WebRTC 도입 이유(REQ-N-001 실시간성)가 사라짐 — 굳이 도입할 이유 없음 |
| C. 원안 그대로 aiortc SFU 구현 | 원본 설계 보존 | 1인/4주 내 완성 불가능에 가까움(ADR-001 사유와 동일) |

## 결정 (Decision)

**A안을 채택한다.** 브라우저 표준 `getUserMedia` + `MediaRecorder` API로
카메라/마이크를 캡처하고, 화면에는 로컬 프리뷰만 표시한다. WebRTC/시그널링
서버/미디어 서버(aiortc, GStreamer)는 이번 MVP에서 완전히 제거한다. 각
턴(질문-답변) 종료 시:
1. 오디오 blob → 서버 업로드 → faster-whisper STT + librosa 음성운율 분석
2. 답변 구간 중 1~2 FPS로 추출한 비디오 프레임 이미지 몇 장 → 서버 업로드 →
   DeepFace 표정 분석
3. 원본 오디오/비디오 blob 자체의 저장 정책은 §"원본 미디어 보관 정책"
   (2026-09-07 확정) 참조.

## 결과/트레이드오프 (Consequences)

- 포기하는 것: 실시간 화상 통화 경험, WebRTC 저지연 스트리밍 스택 전체.
- 얻는 것: 신호서버/미디어서버/STUN·TURN 인프라가 통째로 제거되어 구현
  범위가 크게 줄어듦 — 4주 내 완성 가능성이 실질적으로 올라감.

## 원본 미디어 보관 정책 (2026-09-07 사용자 확정 — 원칙 8 승인 완료)

AI가 제시한 두 후보(즉시 폐기 vs 지원자 삭제 전까지 보관) 중 **"지원자가
직접 삭제하기 전까지 로컬 디스크에 보관"**을 사용자가 선택했습니다.

- **저장 방식**: 턴별 원본 오디오 blob과 비디오 프레임 샘플을
  `MEDIA_ASSETS` 테이블(ADR-003 ERD에 추가, 아래 참조)로 관리하며,
  실제 파일은 서버 로컬 디스크의 암호화된 볼륨(예: 파일시스템 레벨 암호화
  또는 저장 전 애플리케이션 레벨 AES 암호화)에 저장한다. DB에는 파일
  경로/암호화 여부/생성시각만 기록한다.
- **삭제 트리거**: (1) 지원자가 리포트 화면에서 "원본 영상/음성 삭제"를
  직접 요청하는 API 호출, 또는 (2) ADR-006(계정 탈퇴 정책)에 따른 유예기간
  만료 시 계정 전체 파기와 함께 연쇄 삭제(cascade). 두 경로 모두 파일과
  `MEDIA_ASSETS` 행을 물리적으로 완전 삭제한다(소프트 삭제 아님 — 원본
  미디어 자체는 "삭제 즉시 영구 삭제"가 원칙, 계정처럼 유예기간을 두지
  않는다. 이유: 생체정보이므로 보존 기간을 최소화하는 것이 원칙 7과
  일치).
- **ERD**: `MEDIA_ASSETS` 엔티티로 표현하며, 단일 진실 공급원은
  `docs/adr/adr-003-data-stack.md`의 erDiagram(2026-09-07 갱신본)이다 —
  여기서 중복 기재하지 않는다(harness_00 원칙 7).
- **영향받는 요구사항**: REQ-N-003(생체데이터 보호)은 "즉시 삭제"가 아니라
  "요청 시 삭제 + 암호화 저장"으로 재정의됨. `docs/trd/aimock_master_trd.md`
  §3 N-003과 §5 인수조건에 반영 필요(AC 추가: "지원자가 원본 삭제를
  요청하면 해당 파일과 DB 레코드가 즉시 삭제된다").
- **작업지시서 반영 필요**: U2-a/U3-a 단위 TRD 작성 시 파일 암호화 방식
  (라이브러리)과 삭제 API 엔드포인트를 §1 범위에 명시할 것.
