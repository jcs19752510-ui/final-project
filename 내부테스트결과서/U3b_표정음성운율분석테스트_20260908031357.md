## §2. 실제 라이브러리로 발견하고 해결한 실전 이슈 4건

1. **DeepFace가 신형 TensorFlow(2.21)와 바로 호환 안 됨** — "tf-keras package"가
   별도로 필요하다는 것을 실제 실행 중 발견. `requirements.txt`에
   `tf-keras==2.21.0` 추가로 해결.
2. **opencv-python과 opencv-python-headless 동시 설치 시 `cv2` 모듈이
   깨짐**(`CascadeClassifier` 속성 없음 에러) — 로컬 개발 환경(아나콘다)에
   이미 `opencv-python 5.0.0.93`이 설치돼 있던 것과 이번에 추가한
   `opencv-python-headless`가 충돌. **로컬 환경의 `opencv-python`을
   `4.10.0.84`로 강제 재설치해 해결**했습니다 — ⚠️ **이건 이 프로젝트
   폴더 밖, 사용자 컴퓨터의 공용 아나콘다 환경에 영향을 준 변경입니다.**
   다른 프로젝트가 opencv 5.x 특정 기능에 의존한다면 확인이 필요할 수
   있습니다(Docker 이미지는 이 충돌이 원천적으로 없어 별도 조치 불필요 —
   `opencv-python-headless`만 깨끗하게 설치됨).
3. **librosa가 m4a(AAC)를 기본적으로 못 읽음** — `soundfile`(libsndfile)이
   AAC 컨테이너를 지원하지 않고, 대체 경로인 `audioread`는 시스템
   `ffmpeg` 바이너리가 있어야 동작. 로컬엔 없어서 실패 → `imageio-ffmpeg`
   (pip, 로컬 검증용) 및 **Docker 이미지에 `apt-get install ffmpeg`
   추가**(`src/backend/Dockerfile`)로 실제 배포 환경에서 해결.
4. **Windows 콘솔(cp949)에서 DeepFace의 이모지 포함 로그가 인코딩 에러를
   내며 진짜 원인을 가림** — "모델 다운로드 실패"로 보였던 에러의 실제
   원인은 `UnicodeEncodeError`(cp949가 🔗 이모지를 못 씀)였음.
   `PYTHONIOENCODING=utf-8`로 우회 확인(로컬 진단용, 앱 코드 변경 불필요 —
   Docker/Linux는 기본 UTF-8이라 이 문제 자체가 없음).

  라이브러리 타입 스텁 없음)만 남음.

## §4. Docker 컨테이너(실제 배포 환경) 재검증 — 추가 이슈 2건 더 발견·해결

이미지 재빌드 후 실제 API(회원가입→면접 시작→미디어 업로드→리포트 생성)
전체 흐름으로 재검증하는 과정에서 로컬에는 없었던 이슈를 2건 더 발견:

5. **deepface가 자체적으로 설치하는 `opencv-python`이 버전 미고정이라
   pip가 최신(5.0.0.93)을 깔았는데, 이 버전은 얼굴 검출용 haarcascade
   XML 데이터 파일 자체를 wheel에 안 담고 있었음**(`cv2/data/`에
   `__init__.py`만 있고 실제 `.xml` 파일이 없음 — 실제 확인함). →
   `requirements.txt`에 `opencv-python==4.10.0.84` 명시적 고정으로 해결
   (로컬에서 이미 이 버전으로 성공 검증했던 것과 동일 버전).
6. **curl로 파일 업로드 시 스크래치 경로가 260자 넘는 긴 경로라 Windows
   네이티브 curl이 파일을 못 엶**(`curl: (26)`) — 짧은 경로
   (`C:\tmp\...`)로 복사해 우회(테스트 스크립트 문제, 앱 코드와 무관).

이미지를 세 번 재빌드(① ffmpeg+tf-keras 추가 → ② opencv-python-headless
제거 → ③ opencv-python 버전 고정)한 끝에, **실제 컨테이너에서 실제 API
호출로 최종 성공**:

```json
"voice_prosody": [{"turn_index": 0, "energy_mean": 0.11995, "pitch_mean_hz": 115.23}],
"emotion_timeline": [{"confidence": 0.9531, "turn_index": 0, "dominant_emotion": "neutral"}]
```

로컬 직접 스크립트 검증(§1)과 완전히 동일한 수치 — 실제 배포 환경에서도
정확히 같게 동작함을 확인.
