## §3. 특이사항 / 발견 사항

### §3-1. AC-F6 커버리지 제약 (환경 제약, 버그 아님)
Claude Browser 도구는 `<input type="file">`에 실제 파일을 JS로 주입할 수
없음(`InvalidStateError: ... may only be programmatically set to the empty
string` — 브라우저 보안 정책, 도구 한계 아님). 따라서 브라우저 UI로 오디오
업로드 끝까지 클릭해 보는 것은 불가능했음. 대신:
1. 프론트가 실제로 보내는 것과 동일한 필드명(`turn_index`, `audio`)으로
   curl multipart 요청을 실제 백엔드에 보내 계약이 맞는지 확인(422 검증
   에러 없이 정상 파싱되고, 이후 LLM 503으로 이어짐 — 필드명이 틀렸다면
   422가 먼저 났을 것).
2. 마이크 권한이 없는 이 브라우저 환경에서 "녹음 시작" 클릭 시 폴백
   안내("마이크 접근에 실패했습니다...")가 정상 노출되는 것을 확인 —
   에러 상황에서도 화면이 깨지지 않음(TRD §0-1 요건).
- **사람이 결정할 것**: `GEMINI_API_KEY` 확보 후 실제 브라우저 마이크로
  녹음→제출→다음 질문 갱신까지 재검증 필요(A0 §4 기존 항목과 동일).

### §3-2. 실제 버그 발견 및 수정 — ReportPage의 409 처리 오류
**발견**: `POST /interviews/{id}/report`가 409를 반환하는 실제 조건은
`src/backend/app/services/report_service.py`의
`if interview.status != "completed": raise ConflictError("완료된 면접만
리포트를 생성할 수 있습니다.")` — 즉 "면접이 아직 안 끝남" 하나뿐이고,
"리포트를 이미 생성 중"이라는 상태/코드는 백엔드에 아예 존재하지 않음
(원본 코드 확인 결과, `docs/handoff/aimock_a0_handoff.md`의 "live 상태
생성 시도(409)" 표현은 정확히는 "면접 상태가 아직 live(미완료)인 채로
생성 시도"라는 뜻이었음).

**증상**: 종료(`/end`) 안 한 면접에 대해 "리포트 생성하기"를 눌렀더니
프론트가 "리포트를 이미 생성하는 중입니다"라는, 실제로는 일어나지 않는
상황을 안내하는 잘못된 메시지를 보여줌(개발 중 AI가 실제 코드를 안 보고
추측으로 채운 부분).

**수정**: `src/frontend/src/pages/ReportPage.tsx` — 409 상태를 하드코딩
문구 대신 서버가 보내주는 실제 `error.message`를 그대로 노출하도록 변경.
수정 후 실제 브라우저로 재검증(§2 AC-F8 행 참조) — 면접 종료 전 409 시
서버 메시지, 종료 후 `GEMINI_API_KEY` 없을 때 503 메시지가 각각 정확히
노출됨을 확인.

**판단 근거 기록**: 하네스 원칙 6(원본 우선) — 스펙/추정 문구와 실제 코드가
다르면 실제 코드 쪽을 따르고, 이 편차를 보고한다.

### §3-3. 발견된 버그 아님(참고) — 브라우저 자동화 도구의 클릭 좌표 이슈
테스트 중 `ref` 기반 클릭이 HMR(핫모듈교체)나 Monaco 에디터의 비동기
레이아웃 확정 직후에는 잘못된 좌표를 때리는 경우가 있었음(예: "코드 실행
및 제출" 버튼을 클릭했는데 그 아래 "리포트 화면으로 이동"이 눌림). 이는
프론트엔드 코드의 문제가 아니라 이번 세션의 브라우저 자동화 도구 자체의
타이밍 이슈로 판단(스크린샷 직후 짧은 `wait`을 넣거나 좌표 재확인으로
우회). 실사용자가 마우스로 직접 클릭할 때는 발생하지 않는 문제.
