# 내부테스트결과서 — 로컬 pytest가 실제 개발 DB를 매번 삭제하던 버그

## 문서 정보
- 일시: 2026-09-08 12:12
- 심각도: **높음(데이터 유실)**
- 발견 경위: 사용자가 실제 리허설 중 이전에 잘 되던 `readonlytest@example.com`
  계정으로 로그인이 안 된다고 보고("이메일 또는 비밀번호가 올바르지
  않습니다"). 로그인 로직 자체가 아니라 데이터가 사라진 것이 원인이었음.

## 원인 (실제 DB 조회로 확인, 추측 아님)

`tests/backend/conftest.py`의 `DATABASE_URL` 기본값이:
```
postgresql+asyncpg://aimock:aimock_dev_only@localhost:55432/aimock
```
→ **실제 `docker compose`로 띄운 개발 서버가 쓰는 것과 완전히 같은
데이터베이스("aimock")**를 가리키고 있었다.

그런데 같은 파일의 `_clean_db` 픽스처(`autouse=True`)는 **매 테스트
시작 전에 모든 테이블을 TRUNCATE**한다(테스트끼리 서로 영향 안 주게
하려는 의도 자체는 정상). 문제는 이게 "테스트 전용 DB"가 아니라
**실제 운영 중인 개발 DB**에 대고 실행되고 있었다는 것 — 즉, 이번
세션 내내 코드를 고칠 때마다 회귀 확인용으로 돌린 `pytest`가 **그때마다
실제 회원가입 계정·면접 기록을 전부 삭제**하고 있었다.

**검증**: 사고 전후 실제 DB의 사용자 수를 확인.
- pytest 실행 전 사용자: `candidate@example.com`, `groqtest@example.com`, `demo@example.com`(3명)
- pytest 실행(52 passed) → **실행 후에도 동일하게 3명 유지** (수정 후 재검증)
- (참고) 수정 전 상태로 역산하면, 이 세션에서 만들었던 수십 개의 테스트
  계정(`readonlytest`, `hardentest`, `finaltest`, `u3btest`,
  `cameratest`, `nginxtest`, `mediatest` 등)이 이후 pytest 실행 때마다
  삭제되어 최종적으로 가장 마지막에 만든 것 1~2개만 남아있었던 것으로
  설명됨.

**CI는 원래부터 안전했다**: `.github/workflows/ci.yml`은 처음부터 CI
전용 임시 Postgres 컨테이너에 `POSTGRES_DB: aimock_test`(별도 DB)를
쓰고 있었다 — 이 버그는 **로컬에서 직접 `pytest` 명령을 실행할 때만**
발생했다.

## 수정
`tests/backend/conftest.py`의 `DATABASE_URL` 기본값을 CI와 동일한
이름인 `aimock_test`로 변경:
```
postgresql+asyncpg://aimock:aimock_dev_only@localhost:55432/aimock_test
```
로컬 Postgres에 `aimock_test` 데이터베이스를 새로 생성하고
`alembic upgrade head`로 스키마 적용 완료.

## 검증

## 남은 것 / 참고
- 사용자님이 쓰시던 `readonlytest@example.com` 등 이전 테스트 계정들은
  **복구 불가**(이미 삭제됨, 백업 없음) — 다시 회원가입해야 함. 새로
  `demo@example.com` / `demopass123` 계정을 만들어 드림.
- 이번 사고로 인한 실제 서비스 데이터(진짜 지원자 정보 등)는 없었음 —
  전부 이번 세션에서 만든 테스트용 더미 계정이라 실질적 피해는 없음.
  다만 "테스트 실행이 실 데이터를 지울 수 있다"는 구조적 위험은 이번에
  확실히 제거함.
- 앞으로 로컬에서 `pytest` 실행 시 자동으로 `aimock_test`를 쓰므로,
  개발 서버로 로그인해서 만든 계정/면접 데이터는 더 이상 영향받지 않음.
