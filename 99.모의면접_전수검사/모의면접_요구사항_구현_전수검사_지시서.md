## 감사 원칙 (Claude Code가 반드시 지켜야 할 규칙)

1. 아래 매트릭스 A~G의 **모든 행을 빠짐없이** 채운다. 판단이 애매한 항목도 건너뛰지 않고 "확인 불가 — 이유"로 명시한다.
2. "구현 상태"는 반드시 다음 4가지 중 하나로만 표기한다:
   **완전구현 / 부분구현 / 미구현 / 설계와 다르게 구현됨**
3. 모든 판정에는 실제 코드 근거(파일 경로:라인번호, 함수/클래스명)를 반드시 첨부한다. **근거 없이 "구현됨"이라고 쓰는 것은 금지.**
4. F(보안 체크리스트)는 특히 꼼꼼히 검사하고, 발견된 취약점은 심각도(상/중/하)를 매겨 별도 목록으로 정리한다.
5. 최종 산출물은 마크다운 표 형태로, 리더가 5분 안에 전체 그림을 파악할 수 있도록 정리한다.
6. **코드는 절대 수정하지 않고, 검사 결과 리포트만 작성한다.**

## F. 보안 점검 체크리스트 (20년차 보안담당자 관점 — 심각도 상/중/하 표기)

- [ ] API 키/시크릿이 코드에 하드코딩되어 있지 않은가 (.env / secret manager 사용 확인)
- [ ] `.env`가 `.gitignore`에 포함되어 있는가, git 커밋 이력에 노출된 적은 없는가
- [ ] 인증(Authorization: Bearer 등) 로직이 모든 보호 대상 엔드포인트에 실제로 걸려 있는가 — 누락된 엔드포인트 없는가
- [ ] 영상/음성 데이터 저장 시 암호화(AES-256) 적용 여부
- [ ] 전송 구간 TLS 적용 여부 (로컬 개발환경은 예외로 명시)
- [ ] 사용자 요청 시 데이터 영구 삭제 기능이 실제로 동작하는가
- [ ] SQL Injection 등 인젝션 방어 — ORM 파라미터 바인딩 사용 여부
- [ ] 에러 응답에 내부 스택트레이스·민감정보가 노출되지 않는가
- [ ] CORS 설정이 지나치게 열려있지 않은가 (`*` 허용 여부)
- [ ] 파일 업로드(영상/코드 제출) 시 확장자·크기 검증이 있는가

## Claude Code 실행 프롬프트 (아래를 그대로 복사해서 사용)

```
다음 저장소 전체를 대상으로, 첨부된 기획서(SRS/SAD/AI설계/API설계/WBS/QA)의 모든 항목을
위 매트릭스(A~G)에 맞춰 실제 코드베이스와 하나씩 대조하는 전수검사를 수행하라.

규칙:
1. 매트릭스의 모든 행을 빠짐없이 채운다. 애매한 항목도 "확인 불가 - 이유"로 반드시 기재한다.
2. 구현 상태는 [완전구현 / 부분구현 / 미구현 / 설계와 다르게 구현됨] 4가지로만 표기한다.
3. 모든 판정에 실제 코드 근거(파일 경로:라인번호, 함수/클래스명)를 첨부한다.
   근거 없이 "구현됨"이라고 쓰지 않는다.
4. F(보안 체크리스트)는 발견된 취약점마다 심각도(상/중/하)를 매겨 별도 목록으로 정리한다.
5. 최종 산출물은 마크다운 표 형태로 작성한다.
6. 코드는 절대 수정하지 않는다. 검사 결과 리포트만 작성한다.
```

## 산출물 활용 팁

- "미구현" 항목 중 실제로 필요한 것과, 현실적으로 스코프 아웃(제외)할 것을 구분해서 다음 스프린트 계획에 반영하세요.
- "설계와 다르게 구현됨" 항목은 의도적 변경인지 실수인지 먼저 확인하세요 — 필요하면 설계 문서 쪽을 업데이트하는 게 맞습니다.
- F 체크리스트에서 "상" 심각도가 하나라도 나오면, 다른 작업보다 우선순위를 두고 먼저 처리하세요.
