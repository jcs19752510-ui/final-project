## 이번 세션에서 AI가 사람 확인 없이 자동으로 결정하고 진행한 항목

위 4가지 승인 범위 "안에서" 구체적인 라이브러리/도구를 고르는 것은 매번
되묻지 않고 20년차 아키텍트 판단으로 자동 결정했습니다. 근거를 남깁니다.

1. **LLM 공급자: Google Gemini API 무료 티어**
   - 근거: 무료이면서 멀티모달(이미지 입력) 지원 → 원본 기획의 화이트보드
     평가(GPT-4V) 기능까지 별도 서비스 없이 커버 가능한 유일한 무료 옵션.
   - 되돌리기 난이도: 낮음 — LLM 클라이언트를 어댑터 패턴으로 구현하므로
     추후 Groq/Ollama 등으로 교체 가능.

2. **STT: faster-whisper 로컬 실행** (Deepgram 대체)
   - 근거: 무료·오프라인이며 턴 기반 구조에서는 실시간 스트리밍이 필요
     없어 배치 처리로도 요구사항을 만족.

3. **TTS: 브라우저 내장 Web Speech API** (Hume AI/ElevenLabs 대체)
   - 근거: 서버 인프라·비용 0. 감정적 어조 제어 기능은 포기.

4. **데이터 스택: PostgreSQL + pgvector 단일 DB, Redis/Celery 제거**
   (Oracle/Pinecone/Redis/Celery 대체)
   - 근거: 컴포넌트 수를 최소화해 1인이 4주 내 안정적으로 운영 가능한
     수준으로 축소. MVP 트래픽 규모에서 비동기 큐 없이도 충분.

5. **미디어 처리: WebRTC SFU/aiortc 완전 제거, 브라우저 MediaRecorder로
   턴 단위 캡처 후 업로드**
   - 근거: ADR-001(턴 기반)의 직접적 결과 — 실시간 서버 분기 처리 자체가
     불필요해짐.

6. **배포: 로컬 Docker Compose 기본, 무료 PaaS는 Could-have**
   (Kubernetes/GCP 대체)
   - 근거: 1인/4주/무예산 조건에서 오케스트레이션 학습·구축이 핵심가치
     (AI 면접 기능)와 무관한 시간 소모이기 때문.

7. **하네스 적용 범위 축소: `harness_11`(RACI), `harness_12`(변경관리) 등
   팀 단위 거버넌스 문서는 이번 프로젝트에서 정식 산출물로 작성하지 않음**
   - 근거: 결정권자가 사용자 1인뿐이라 "역할 분담/승인 라인"을 문서화할
     대상 자체가 없음. 대신 `harness_00`의 8원칙과 ADR/TRD/AC 체계(1인
     프로젝트에도 유효한 최소 경로)는 그대로 적용.
   - 이 결정 자체도 20년차 PM이라면 마땅히 할 "프로세스를 프로젝트 규모에
     맞게 재단하는" 판단이라고 보아 사람에게 되묻지 않고 진행했습니다.
